# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Common Development Commands

### Development
- `npm run dev` - Start development server with HMR (runs frontend Vite dev server and backend Express server)
- `npm run build` - Build for production (builds both frontend and backend)
- `npm start` - Start production server

### TypeScript
- `npm run check` - Type check the entire codebase without emitting files

### Database
- `npm run db:push` - Push database schema changes using Drizzle Kit

### Environment Setup
Ensure you have a `.env` file with:
- `DATABASE_URL` - PostgreSQL connection string (Neon Database)
- `NODE_ENV` - Set to "development" for dev mode
- `GEMINI_API_KEY` - Google Gemini API key for AI content generation

## High-Level Architecture

### Project Structure
This is a full-stack TypeScript application with a clear separation of concerns:

- **`client/`** - React frontend (Vite build system)
- **`server/`** - Express.js backend with TypeScript
- **`shared/`** - Shared schemas and types between client and server
- **`migrations/`** - Database migration files (generated by Drizzle Kit)
- **`uploads/`** - File upload storage directory

### Tech Stack Overview

**Frontend:**
- React 18 + TypeScript with Vite
- Wouter for lightweight routing (not React Router)
- TanStack Query for server state management
- Shadcn/UI components (Radix UI + Tailwind CSS)
- React Hook Form with Zod validation
- TipTap rich text editor
- React DnD for drag-and-drop functionality

**Backend:**
- Express.js with TypeScript and ES modules
- Drizzle ORM with PostgreSQL (Neon Database)
- Multer for file uploads
- Google Gemini AI integration
- Rate limiting for AI endpoints

### Database Schema Architecture
The application uses a flexible content management system with these core entities:

- **`courses`** - Main course container with metadata and Rise 360-like features
- **`modules`** - Course chapters/lessons with ordering and navigation settings  
- **`content_blocks`** - Flexible content system using JSON storage for different block types
- **`reference_files`** - File attachments per course
- **`course_themes`** - Theming system for course appearance
- **`media_assets`** - Media files with metadata
- **`question_banks`** & **`quiz_questions`** - Quiz and assessment system

### Key Architectural Patternsnpm 

**Repository Pattern**: Data access is centralized in `server/storage.ts` with CRUD operations for each entity.

**Shared Validation**: Zod schemas in `shared/schema.ts` are used for both frontend forms and backend API validation.

**Type-Safe Database**: Drizzle ORM provides full TypeScript support with schema-first approach.

**Component Architecture**: 
- UI components in `client/src/components/ui/` (Shadcn/UI)
- Feature components in `client/src/components/course/`
- Page-level components in `client/src/pages/`

### AI Integration Architecture

**Content Generation**: Google Gemini 2.5 Flash provides AI-powered content generation with:
- Automatic text generation when adding content blocks
- Inline AI assistant for text improvements
- Custom prompt handling with existing content context
- Rate limiting (30 requests/minute per IP)
- Fallback behavior for failed generations

**AI Service Layer**: `server/ai-service.ts` handles all AI operations with proper error handling and rate limiting.

### Content Block System

The application uses a flexible content block system where each block has:
- **Type**: text, image, video, quiz, etc.
- **Content**: JSON-based storage allowing different structures per type
- **Styling**: Configurable appearance options
- **Ordering**: Drag-and-drop reordering with React DnD
- **Interactions**: Hover actions (duplicate, delete, move)

### Rich Text Editing
- Always-on editing mode (no separate edit state)
- Floating toolbar that appears on focus
- Auto-save functionality (1 second after typing stops)
- TipTap-based with standard formatting options

### Development Workflow
1. Frontend runs on Vite dev server with HMR
2. Backend runs on Express with tsx for TypeScript execution
3. Database changes managed through Drizzle Kit migrations
4. Shared types ensure consistency between client and server
5. File uploads handled via Multer to local filesystem

### API Design Patterns
- RESTful endpoints with consistent structure
- Nested resources: `/api/courses/:id/modules`, `/api/modules/:id/content-blocks`
- Zod validation on all endpoints
- Centralized error handling
- JSON-based responses with proper HTTP status codes

## Important Development Notes

### Path Aliases
- `@/*` maps to `client/src/*`
- `@shared/*` maps to `shared/*`
- `@assets/*` maps to `attached_assets/*`

### File Upload System
- 10MB file size limit
- Accepts: PDF, DOC, DOCX, TXT files
- Files stored in `uploads/` directory
- Validation handled by Multer middleware

### Environment-Specific Behavior
- Development: Vite dev server with HMR and Replit plugins
- Production: Static file serving from `dist/public`
- Database migrations: Run via `npm run db:push`

### Content Block Menu System
- Bottom toolbar for quick access (Text, Image, Video, Quiz)
- Left sidebar panel for full block type selection
- Portal rendering for proper positioning
- Subtle color coding by category (violet for AI, blue for media, etc.)

### AI Rate Limiting
The AI service has built-in rate limiting to prevent abuse. When developing AI features, be aware of the 30 requests per minute limit per IP address.
